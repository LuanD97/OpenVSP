# Pinned versions for the dev venv's third-party (non-editable) dependencies.
#
# Referenced from requirements-dev.txt via "-c constraints.txt" so that a resolver
# re-run (e.g. re-installing openvsp in place after a source change) can never
# silently bump a shared dependency out from under an already-compiled extension.
# That's not hypothetical: pip once silently upgraded numpy 1.26.4 -> 2.5.2 while
# reinstalling just the openvsp package, and numpy 2.x refuses to load a module
# compiled against the numpy 1.x C-API (hard crash on import, not a warning).
# scipy and opencv-python (pulled in by AvlPy/CHARM/utilities below) have the same
# failure mode in reverse: left unconstrained they resolve to numpy>=2-only
# releases and drag numpy along with them.
#
# None of AvlPy/CHARM/utilities/vsp_airfoils/pyPMARC's own setup.py put an upper
# bound on numpy either, so this file is the only thing holding the whole graph on
# numpy 1.x until _vsp is rebuilt against numpy>=2 headers (ABI-compatible with
# both 1.x and 2.x runtimes) -- see the numpy comment in openvsp/setup.py.in.
#
# Regenerate after deliberately bumping a version: run `pip freeze` in the dev
# venv, drop the "-e ..." editable local packages (vsp_airfoils, utilities,
# degen_geom, openvsp_config, openvsp, CHARM, AvlPy, pyPMARC -- those track this
# source tree, not a pinned release), and update the versions below.
